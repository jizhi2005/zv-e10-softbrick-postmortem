## 一、先修正三条此前记录里的错误

### ❌ 错误 1：万用表校准倍数

| | 此前记录 | 实测修正 |
|---|---|---|
| 倍数 | "偏高 21%" | **偏高 51.5%** |
| 依据 | 未记录 | 3V3 脚真值 3.30 V → 表读 5.0 V；5V 脚真值 5.15 V → 表读 7.8 V |

**换算公式：真值 = 表读 ÷ 1.515**

**此前那些"VBUS 5.12 V""A7 1.73 V"等结论，都是按错误的 21% 换算出来的，数值本身不可靠**（虽然"电压存在"这个定性结论不变）。

### ❌ 错误 2："A7 有相机侧 1.73 V 上拉，说明线是活的"

**这个推断站不住。** 真正情况是：

```
pin 39 (gpio1-7) = 我们的 D− 线: input bias PULL UP  ← 我们自己的内部上拉一直开着
pin 40 (gpio1-8) = 我们的 D+ 线: input bias PULL UP  ← 同上
```

**我们读到的"2.x V"里，有多少来自相机、多少来自我们自己，从来没分离过。**

### ❌ 错误 3："D− = 0 V 说明接线断了"

**那次 D− 读 0 是因为 `parity_probe` 正在驱动它**（开漏输出 233 µs 方波，万用表读到被拉低的平均值）。
**探针一停，D− 立刻回到 2.x V。** 当时的"接线断了"判断是错的。

**教训：量电压之前先确认没有进程在驱动那条线。**

## 二、新增的实测证据

### 2.1 接线逐点确认（相机关机、不接相机两种状态都测过）

| # | 接线 | 验证 | 结果 |
|---|---|---|---|
| ① | 下排1 (GND) → JP2 GND | 电压基准 | ✅ |
| ② | 下排9 (VCC/A9) → JP2 5V | 拔掉相机后仍有 5V → **是我们在供电** | ✅ |
| ③ | 下排5 (A5) → 5.1k → GND | A5 = 0 V | ✅ |
| ④ | 上排8 (B5) → 下排5 (A5) | B5 = 0 V，与 A5 同电位 | ✅ |
| ⑤ | 下排6 (D+) → 470Ω → gpio40 | 两端压降 ≈ 0 V | ✅ |
| ⑥ | 下排7 (D−) → gpio39 | 两端压降 ≈ 0 V | ✅ |

**结论：接线无误，两个 CC 都是 Rd 下拉（DAM 条件成立），传输路径无压降。**

### 2.2 供电方向确认

- **拔掉相机后，下排9 (VCC) 仍有 5 V** → **是我们（JP2 5V）在给相机供电**
- **相机只装电池、不接 24pin 板时，能正常循环启动** → VBUS 对启动不是必需
- 与上游一致（上游文档也提到 Pico 5V 与 Mac 5V 会在相机 VBUS 上"顶在一起"）

### 2.3 隔离测量：只剩相机侧时 D+/D− 的电平

**把 gpio39/gpio40 那两根线从 JP5 拔掉（焊盘只连相机），量：**

| 测点 | 读数 | 备注 |
|---|---|---|
| 下排6（D+） | **2.8 V**（此前一次测到 0，可能状态不同） | 相机侧有偏置 |
| 下排7（D−） | **2.2 V** | 相机侧有偏置 |

**OFF / ON 切换时，两个电压都不变化。**

> ⚠️ 注意：这两次隔离测量的结果不一致（一次 D+=0、一次 D+=2.8 V），
> 说明相机状态或接触有变化，**这个数据点不可靠，不能作为判据**。

### 2.4 ★ 决定性实验：D− 在相机启动全程无任何信号活动

**用纳秒精度采样器（`tools/edgecap.c`）连续采样 D− 18 秒，覆盖相机约 7 次启动循环：**

```
edgecap: sampling gpio39 (bank1 @0xFEC20000 EXT_PORT bit 7)
         18 s, trigger=none, max 4000 transitions, window 4000 us
         EXT_PORT=0xA36FF883 -> gpio39 reads 1
transitions seen=0  recorded=0  triggered=0
NOTHING CAPTURED
```

**18 秒内 0 次电平跳变，恒定高电平。**

> **重要限制（不要过度解读）：** 这次采样时**我们这侧并没有在发送信号**，
> 线是空闲的。所以"0 跳变"只证明**空闲线上没有噪声/活动**，**不能证明引脚不传递信号**。
> 这个实验的结论是"相机在启动过程中不会主动驱动 D−"，而不是"信号进不去"。

### 2.5 反插（翻转 180°）实测

依据 ILCE-7M4-RE issue #3 里 `SerialDestructor` 的观察
（"只有 USB3 口、只有一个特定方向，相机 LED 才会出现脉冲"）：

**把 24pin 板翻 180° 插（等价于数据落到 B 排触点），重跑垃圾方波 → 无反应。**

> 补充：ZV-E10 是 USB 2.0 全速设备，Cube 用 16pin 母座时 A7/B7 在板上本就并联，
> 所以"反插"与"改用 B7 焊盘"在电气上等价，不需要重复测。

### 2.6 ★ 新判据：用 USB 身份而不是指示灯

**这是此前从未用过的判据。**

上游流程：注入 stage1 → stage1 建立 USB 设备 `ZVE10-fastboot` → 把相机 USB 移到电脑。

**我们这样做：**

```
1. 24pin 板注入官方 stage1.bin（sha256 已核对）
   参数：--record-gap 2000 --reset-us 10 --settle-ms 100 --seconds 120
2. 立刻拔下 24pin 板，换普通 USB-C 数据线接到 RK3588 的 USB-A 口
3. 用 watch_usb.sh 监控 /sys/bus/usb 与 dmesg
```

**结果：整段监控只看到 `054c:0994`（"USB Charger"）每 2.6 秒循环枚举。**

```
[4511.021890] usb 2-1.3: new full-speed USB device number 21 using ehci-platform
[4511.120728] usb 2-1.3: New USB device found, idVendor=054c, idProduct=0994
[4511.120756] Product: USB Charger
[4511.353861] usb 2-1.3: USB disconnect, device number 21
[4513.668561] usb 2-1.3: new full-speed USB device number 22 ...
```

**没有 `18d1:4ee0`，没有 `ZVE10-fastboot`，没有任何新设备。**

### 2.7 已核对的上游 payload 与参数（确认我们这边没配错）

| 项目 | 上游值 | 我们用的 | 核对 |
|---|---|---|---|
| `prebuilt/stage1.bin` | 7636 B，sha256 `8573b5d1…` | **同一文件，sha256 一致（板上复核过）** | ✅ |

## 三、这一天得到的确定结论

### ✅ 可以确定的事实

1. **相机硬件没坏。** 每 2.66 秒正常走完 BootROM → Loader → 内核，Loader 每轮都在 USB 上枚举 `054c:0994`。
2. **接线完全正确。** 逐点电压、压降、CC 双下拉全部验证，包括反插。
3. **注入端配置完全正确。** 官方 payload（sha256 一致）、上游参数（2 ms / 100 ms / 10 µs）、波形纳秒级实测精确。
4. **相机在启动过程中不会主动驱动 D−。** 18 秒纳秒采样 0 跳变（但要读作"空闲无活动"，不是"信号进不去"）。
5. **USB 身份判据下也无反应。** 换普通数据线后，相机始终只有 `054c:0994`。

### ❓ 仍然无法确定的

**A7(D−) 在相机内部是否接到了 `BOOT_SERIAL_IN`（BGA G18/L19）。**

外部能做的判别手段已经用尽：
- 电压/压降 → 只能证明"线通了"，不能证明"通到哪个引脚"
- 隔离测量 → 两次结果不一致，不可靠
- 纳秒采样 → 空闲时无活动，无法区分"没接"和"接了但 ROM 不采样"

**这个只能靠点位图或拆机直接测量。**

### 🔍 还没问到的关键问题

`dino2048` 明确回复"**我在自己的 ZV-E10 gen1 上验证过 A7/A6 接线，电脑识别为 `ZVE10-fastboot`，响应了 fastboot 的 version 和 product 查询**"，
并建议用**同款 RP2040 Pico + 他的发送固件**做对照。

**但还有一个问题没问：他的 24pin 板插座是 16pin 还是 24pin，以及他那条线的具体规格。**

如果他的板/线与我们不同（例如插座内部 A7 触点接通方式不同），那可能是我们没复刻到的唯一硬件差异。
