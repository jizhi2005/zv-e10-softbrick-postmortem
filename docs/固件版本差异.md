# 固件版本差异（2.02 vs 2.03）— 根因

> **更新（2026-11-27 晚）：用户确认这台相机更新过到 2.03。
> 上游文档明确写着 2.02 = `30110_05.2025031501`、2.03 = `30110_06.2026060501`。
> 而所有 fastboot / BootROM 成功记录全部绑定在 2.02 上。**

---

## 一、决定性的文档对应关系

来自 `dino2048/zv-e10-toolkit` 的 `linux/docs/jiritsu.zh-CN.md`（第 9–11 行）：

| 系统 | 固件 | 该版本走的后端 | 实测范围 |
|---|---|---|---|
| **2.02** | **`30110_05.2025031501`** | 原终端 / FileControl | 完整双遍备份，约 12 MiB/s |
| **2.03** | **`30110_06.2026060501`** | **Jiritsu（完全不同的一套）** | 持续 root shell；完整用户区+B0/B1 单遍 |
| 2.02 | — | 可选 Jiritsu | 此后端尚未完成该版本实机验证 |

**本机可用固件（从 `firmware.fdat` 检索，偏移 `0x26240`）：**

```
30110_06.2026060501
```

**= 2.03。用户确认「确实更新过一次，2.03」。**

## 三、上游自己观察到 2.03 的协议行为变了

`jiritsu.zh-CN.md` 第 13 行：

> **“本机 2.03 的旧终端命令通道失败，启用终端前后 FileControl 都返回 `0x80`、0 字节。**
> 这是该设备/会话的结果，不能扩大成所有 2.03 都删除了该协议。”

**关键：他们为 2.03 专门做了一整套 Jiritsu 后端，因为 2.02 的旧方法在 2.03 上不工作。**

**这说明 Sony 在 2.03 里确实改了东西。**

> ⚠️ 但请注意他们的措辞很谨慎：“不能扩大成所有 2.03 都删除了该协议”。
> 我引用它时也应保持同样的谨慎：**这证明 2.03 有变化，不证明 BootROM 串口启动被完全移除。**

## 四、我们自己的实测结果（与 2.03 假设完全吻合）

| 实验 | 结果 | 与"2.03 不支持 BootROM 串口"是否吻合 |
|---|---|---|
| 垃圾方波（4 次，含拔电池冷启动） | **连 `0x100D` 都没有** | ✅ 完全吻合 |
| 完整 payload（官方 sha256 版） | 无任何错误码 | ✅ |
| 反插 180°（等价 B7/B6） | 无反应 | ✅ |
| USB 身份判据（换普通数据线） | 只有 `054c:0994`，没有 `ZVE10-fastboot` | ✅ |
| 接线（逐点电压/压降/CC 双下拉） | **全部正确** | ✅ 说明不是我们的问题 |
| 波形（纳秒级实测） | **精确** | ✅ |
| payload（sha256 与上游清单一致） | **正确** | ✅ |

**最有说服力的一点：如果 ROM 在采样但内容不对，它必然报错误码
（`0x2002` token / `0x2003` CRC / `0x2004` 记录不完整）。
我们得到的是彻底的沉默——连错误码都没有。这说明 ROM 从未进入串口接收模式。**

## 五、结论

### ✅ 现在可以确定的

1. **相机固件是 2.03（`30110_06.2026060501`）。**
2. **上游所有 fastboot / BootROM 成功记录都在 2.02 上。**
3. **上游明确观察到 2.03 的协议行为与 2.02 不同**（旧终端通道返回 `0x80`）。
4. **我们的所有阴性结果与"2.03 上这条路不成立"完全吻合。**

### ⚠️ 必须诚实标注的不确定

- **"2.03 关闭了 BootROM 串口启动"目前是强推测，不是已证事实。**
  上游只说"2.03 的旧终端协议不工作"，**没有说过 BootROM 串口启动在 2.03 上失败**。
- 我们在 issue 里已直接问 dino2048：**2.03 上 BootROM 串口注入有没有成功过**
  → [issue #8 comment](https://github.com/dino2048/zv-e10-toolkit/issues/8#issuecomment-7220609429)
- `firmware.fdat` 是升级包，理论上等于最新可用固件；用户已确认更新到 2.03，
  两者一致，这一点现在比较可靠了。

### 实践意义

- **买 RP2040 Pico 没有意义** —— 2.03 上没有任何 Pico 成功记录。
  （发送端再精确，改变不了 ROM 不采样的现实。）
- **用户没有做错任何事** —— 接线、波形、payload、参数全部正确且逐项验证。
- **2.03 上能做的是什么？** 上游的 Jiritsu 后端（实测在 2.03 上拿到持续 root shell）。
  但它**需要相机启动到能接受服务会话的程度**，而本机用户态已死。
  这条路的前提不成立。
