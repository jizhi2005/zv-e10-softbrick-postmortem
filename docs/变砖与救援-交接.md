# ZV-E10 变砖与救援 —— 完整交接（2026-11-26）

> 本文记录一次完整的排查过程与结论。目的是：任何人接手时不必重复今天的弯路。

## 一、相机状态

- **机型**：Sony ZV-E10 一代（ILCE-ZV-E10），SoC CXD90045，ARMv7，Linux 3.0.27
- **不是硬件损坏**。是**用户态软砖**：内核、USB、HID 全部正常，只有应用层起不来。
- 现象：开机约 2.7 秒一轮重启循环，指示灯循环闪；USB 只枚举 `054C:0994`（Sony USB Charger HID）。

## 二、变砖的确切原因

2026-11-19 为给 `im.elf` 注入代码，写了 `/etc/zvtui5.so`，用
`__attribute__((alias("zvtui5_start_main")))` 劫持 `__libc_start_main`，并写入
`/etc/ld.so.preload` 指向它。

缺陷（反汇编确认）：

```asm
__libc_start_main:
  8f8: push {r4,r5,r6,r7,r8,r9,sl,fp,lr}
  904: sub  sp, sp, #84
  91c: ldr  r3, [sp, #124]      ; 第 7 参数（位置不符）
  924: ldr  ip, [sp, #120]      ; 第 6 参数
```

alias 包装与真实函数体的栈参数偏移不匹配 ⇒ `init/fini/rtld_fini/stack_end`
读到垃圾值 ⇒ 进程在 `main` 之前崩溃。

而相机是 glibc 2.11.2 / `ld-2.11.2`，**preload 失败/崩溃是全局致命**：
`/etc/ld.so.preload` 对所有动态链接进程生效 ⇒ 每次 `execve` 都失败 ⇒
`/sbin/init` 起不来 ⇒ 内核/看门狗复位。

## 三、修复动作（极小）

### 3.1 方案 A：直接修（最小改动）

**删掉 `/etc/ld.so.preload`，或把它的 FAT 目录项 size 字段清零。**

- `/etc` 在 **nflasha10**（vfat），用户区偏移 `0x0AC00000` = LBA `0x56000`，12 MiB
- 该分区挂载点是 `/tmp`（`/etc` 在其下）
- 上游事故文档记录：整块 12 MB 分区**只变 1 个字节**
- 注意：该 FAT 目录项位置**不保证**是上游文档写的 `0x0C60`（这台相机额外写过
  zvpre/zvtui2/3/4/5.so 与 .orig），**必须先扫描根目录按名字定位**，不能写死偏移

### 3.2 ★ 方案 B：开一个服务接口（推荐，一旦有任何写入通道）

**在 nflasha2 的 `/setting/sen/` 下创建一个内容为 `UU` 的文件 `smode`。**

依据（反汇编 `nflasha3/initrd.img/sbin/init` 得到，完整链条已确认）：

```c
// check_forced_senser()
fd = open("/setting/sen/smode", O_RDONLY);
n  = read(fd, buf, 256);
if (n && strncmp(buf, "UU", 2) == 0 && !is_bis)
        is_forced_senser = 1;
```

```asm
; main() 在 launch_shell() 之前：
ldr  r3, =is_forced_senser
cbz  r3, skip
ldr  r0, ="/usr/bin/sen.elf"
bl   run_bg_process          ; ← initramfs 阶段拉起服务进程
skip:
ldr  r0, ="/usr/bin/net_cmdd.elf"
bl   run_bg_process
```

**为什么这条路比方案 A 好：**

- `/usr/bin/sen.elf` 由 **initramfs** 拉起，**在用户态之前**——不受坏 preload 影响
- `sen.elf` 提供 Sony 的 "Senser" 服务接口（USB `054C:0336`，vendor-specific class FF）
- 本机 Windows 已经装好 `libusb-win32` 驱动（注册表里 0336 → `Service = libusb0`）
- 拿到服务会话即可获得 root shell → 修 `/etc`、恢复原样、以后做触屏/新菜单也能用

**注意**：`/setting/sen/smode` 在出厂包里不存在，是运行时文件。
索尼官方的正常服务模式（PMCA-RE `StartSenser`）需要大容量模式（`0d95`），
也就是需要用户态；只有 `is_forced_senser` 这条 initramfs 旁路绕过了用户态。

**两种方案的共同前提：一次写入通道。** 这是当前唯一缺口。

## 八、教训

1. **先量电压，再写代码**。A7/A6 的空闲电压、开漏能否拉干净，是本项目最晚才做、却最该最先做的测量。
2. **"上游做过"不等于"你能复现"**。物理入口（BGA 球 / 测试点）不同，软件一模一样也没用。
3. **软件移植必须核常量**。ESP32 版 `zve10_multi.ino` 的 `NS_PRE_HI` 用了 23 周期
   （239.6 µs），而 PIO 原件是 `set pindirs,0 [22]`(23) + `jmp`(1) = **24 周期 = 250.0 µs**。
   60 个前导边沿全长错 4.2%，这极可能是之前 60 多个 ESP32 版本全部失败的原因。
   `REC_GAP` 也曾是 2 ms（上游 14.4 ms）。
4. **判据要用不依赖协议的自报信号**。`0x100D`(13 短闪) 是 ROM 自己的奇偶错报告，
   比任何间接现象都硬。听不到它，就说明根本没进串口启动模式。
